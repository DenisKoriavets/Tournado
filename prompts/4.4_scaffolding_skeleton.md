# Prompt 4.4: AI-Harness Instructions Configuration & Walking Skeleton Scaffolding

## AI Role
Act as a Principal Software Architect and Developer Experience (DevEx) Engineer with deep expertise in multi-runtime monorepos, Spring Boot 3 enterprise backends, React modern frontends, Docker orchestration, and AI-assisted software engineering practices.

## Project Context
We are engineering **Tournado** — a web platform for organizing amateur and collegiate esports tournaments (Counter-Strike 2, Brawl Stars, Chess.com).
* **Architectural Decisions (ADR 0001–0009):**
  * Lightweight monorepo with `core/` (Spring Boot 3.3+, Java 21, Maven), `frontend/` (React 19, TypeScript, Vite, Tailwind), and `ai-service/` (Python 3.12, FastAPI).
  * PostgreSQL 16+ as Single Source of Truth (`data-schema.md`), Flyway migrations, UUID primary keys, optimistic locking (`@Version`), UTC `TIMESTAMPTZ`.
  * Modular monolith package-by-feature in `core/` (`identity`, `teams`, `tournaments`, `bracket`, `matches`, `integrations`, `disputes`, `common`).
  * Realtime WebSockets via Spring STOMP (`/ws`), server-calculated timers in PostgreSQL (no Redis for MVP).
  * RFC 7807 Problem Details standardized error handling (`error-format.md`).
  * Docker Compose for 1-command startup (`docker compose up --build`).
* **Input Specifications:**
  1. `docs/requirements.md` (36 MVP User Stories US-01..US-36, Acceptance Criteria).
  2. `docs/analysis/requirements-digest.md` (Entities E1..E13, Business Rules BR-01..BR-60).
  3. `docs/adr/README.md` and ADRs 0001–0009.
  4. `docs/contracts/` (`README.md`, `data-schema.md`, `api-contracts.md`, `error-format.md`).

## Task

### 1. Master AI-Harness Configuration (`CLAUDE.md`, `AGENTS.md`)
Formulate a rigorous, production-grade instructions manual for AI coding assistants and autonomous agents (Claude, Antigravity, Cursor, Copilot) that guarantees code generation will adhere strictly to our design contracts and team constraints:
* **Project Essence & Directory Layout:** Document the monorepo structure, folder responsibilities, and team role ownership for each module.
* **Operational Command Reference:** Prescribe exact, verified commands for running, testing, building, and linting each runtime natively and via Docker Compose.
* **Data Storage & Contract Fidelity:** Mandate that all entities, DTOs, and schemas be verified against `docs/contracts/` prior to writing code. Enforce UUID primary keys, UTC timestamps, and optimistic locking invariants.
* **Modular Monolith Encapsulation:** Define strict inter-module communication rules in `core/` (interfaces and Spring events only, no direct repository cross-injections).
* **Testing Engineering Standards:** Mandate the `givenX_y_shouldZ` naming convention, AssertJ recursive object comparisons against `TestResources`, static wildcard imports, single blank line separation without phase comments, and prohibited redundant verifications.
* **Strict Engineering Prohibitions (The 10 Prohibitions):** Enumerate explicit "Thou Shalt Nots" to prevent AI hallucinations (e.g. no invented DB columns, no custom error JSON formats, no client-side match timers, no sequential IDs, no Redis additions).

### 2. Walking Skeleton Scaffolding Blueprint
Define the initial runnable "Walking Skeleton" file structure connecting all layers without business logic:
* **Backend Core (`core/`):** Maven `pom.xml` with Spring Boot 3 dependencies (Web, Data JPA, Validation, Flyway, WebSocket, Actuator, PostgreSQL), `CoreApplication.java`, health controller exposing `GET /api/health`, and Flyway migration `V1__initial_schema.sql` incorporating the full DDL from `docs/contracts/data-schema.md`.
* **Frontend (`frontend/`):** Vite + React + TypeScript scaffold with a landing stub displaying the Tournado banner, list of planned tournament screens, and an asynchronous connectivity indicator checking `/api/health`.
* **AI Service (`ai-service/`):** Lightweight FastAPI scaffold with `GET /api/v1/ai/health` and deterministic mock for `POST /api/v1/ai/analyze-dispute`.
* **Orchestration & Env:** Root `docker-compose.yml` orchestrating `db`, `mail` (Mailpit), `core`, `frontend`, and `ai-service`, paired with `.env.example`.
* **Documentation:** Clear 1-2 command instructions in root `README.md` for clean-terminal startup and health verification.
