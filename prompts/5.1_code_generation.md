# Prompt 5.1: End-to-End Vertical Slice Code Generation (US-07..US-11)

## Role & Context
Act as a Principal Full-Stack Software Engineer and Systems Architect orchestrating the implementation of the first vertical slice in **Tournado** — a web platform for amateur and collegiate esports tournaments (Counter-Strike 2, Brawl Stars, Chess.com).

* **Architecture Context:**
  * Backend: Java 21, Spring Boot 3.3.5, Spring Data JPA, Flyway, PostgreSQL 16 (`core/`).
  * Frontend: React 19, TypeScript, Vite, Tailwind CSS (`frontend/`).
  * Database: PostgreSQL schema governed by `docs/contracts/data-schema.md` and Flyway migrations.
  * API & Error Contracts: `docs/contracts/api-contracts.md` and `docs/contracts/error-format.md` (RFC 7807 Problem Details).
* **Scope (Epic 3 — US-07..US-11):**
  * `US-07`: Select Discipline & Team Size (CS2: 5v5, Brawl Stars: 3v3, Chess: 1v1).
  * `US-08`: Auto-populate Map Pool per discipline.
  * `US-09`: Bracket Format & Slot Limit (Single Elimination, 8/16/32 slots).
  * `US-10`: Set Tournament Schedule (`registrationDeadlineAt < checkInOpensAt < startTimeAt`).
  * `US-11`: Public Tournament Link & Landing Details View.

## 1. Backend Subagent Generation Prompt (Java / Spring Boot 3)

````markdown
You are the Backend Engineer for Tournado.
Implement the backend vertical slice for Tournament Configuration and Retrieval (US-07..US-11) in accordance with the project contracts.

PROJECT CONSTRAINTS & CONTRACTS:
1. Data schema: docs/contracts/data-schema.md and core/src/main/resources/db/migration/V1__initial_schema.sql.
   - Table `tournaments`: id UUID, name VARCHAR(150), description TEXT, discipline ('CS2','BRAWL_STARS','CHESS'), format 'SINGLE_ELIMINATION', slot_limit (8, 16, 32), status ('DRAFT', 'REGISTRATION_OPEN', 'CHECK_IN_ACTIVE', 'IN_PROGRESS', 'COMPLETED'), registration_deadline_at TIMESTAMPTZ, check_in_opens_at TIMESTAMPTZ, start_time_at TIMESTAMPTZ, cs2_server_connect TEXT, created_by_user_id UUID REFERENCES users(id), created_at, updated_at, version BIGINT NOT NULL DEFAULT 0.
   - Table `tournament_map_pool`: id UUID, tournament_id UUID, map_name VARCHAR(64), sort_order INT.
2. Note on database seeding:
   - `core/src/main/resources/db/migration/V2__seed_system_user.sql`:
     Insert idempotent system organizer user (`00000000-0000-0000-0000-000000000001`, `system.organizer@tournado.kma.ua`) with `ON CONFLICT (id) DO NOTHING;` and default `created_by_user_id` in `TournamentService` to this UUID.
   - `core/src/main/resources/db/migration/V3__seed_sample_tournaments.sql`:
     Seed 6 idempotent initial tournaments across `CS2`, `BRAWL_STARS`, and `CHESS` (`REGISTRATION_OPEN`, `CHECK_IN_ACTIVE`, `IN_PROGRESS`, `COMPLETED`; slots `8`, `16`, `32`) plus their `tournament_map_pool` rows so real PostgreSQL persistence is demonstrable out of the box.
3. API Contracts: docs/contracts/api-contracts.md (Section 3.1 & 3.2):
   - `POST /api/v1/tournaments`: returns 201 Created with full TournamentResponse.
   - `GET /api/v1/tournaments`: returns 200 OK with list of TournamentSummaryResponse.
   - `GET /api/v1/tournaments/{id}`: returns 200 OK with TournamentResponse or 404 Problem Details.
4. Map Pool auto-population (US-08):
   - CS2: ["de_mirage", "de_inferno", "de_nuke", "de_ancient", "de_anubis", "de_dust2", "de_vertigo"]
   - BRAWL_STARS: ["Shooting Star", "Backyard Bowl", "Hard Rock Mine", "Dueling Beetles", "Ring of Fire"]
   - CHESS: ["Blitz 3+2", "Rapid 10+0"]
5. Validation rules (BR-xx):
   - `registrationDeadlineAt < checkInOpensAt AND checkInOpensAt < startTimeAt`
   - Discipline in `CS2`, `BRAWL_STARS`, `CHESS`
   - Slot limit in `8`, `16`, `32`
   - Status defaults to `REGISTRATION_OPEN`
   - Team size: CS2 = 5, BRAWL_STARS = 3, CHESS = 1
6. Error handling (RFC 7807 & docs/contracts/error-format.md):
   - Implement `GlobalExceptionHandler` in `core.common.exception`
   - Emits RFC 7807 ProblemDetail: `type`, `title`, `status`, `detail`, `instance`, `code`, `timestamp`, `invalidParams`.
7. Testing Standards in CLAUDE.md:
   - Tests in `core/src/test/java/com/tournado/core/tournaments/api/TournamentControllerTest.java` and `TournamentServiceTest.java`.
   - Follow `givenX_y_shouldZ` naming convention without using "when" in method names.
   - AssertJ assertions only (`usingRecursiveComparison`).
   - Zero phase comments (`// Given`, `// When`, `// Then`), single blank line separators.
````
