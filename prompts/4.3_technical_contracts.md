# Prompt 4.3: Technical Contracts Design (Database Schema, REST & WebSocket API, Unified Error Format)

## AI Role
Act as an enterprise-grade Lead Systems Architect and API Designer (Staff Software Engineer) with deep expertise in distributed systems design, relational database modeling (PostgreSQL), RESTful API design, and WebSocket STOMP messaging protocols.

## Project Context
We are developing **Tournado** — a modular web platform for organizing and running amateur and collegiate esports tournaments.
* **Supported Disciplines:** Counter-Strike 2 (5v5), Brawl Stars (3v3), Chess.com (1v1).
* **Technology Stack (agreed upon in ADR 0001–0009):**
  * Frontend: React + TypeScript + Vite.
  * Backend Core: Java 21 + Spring Boot 3 (modular monolith).
  * Database: PostgreSQL + Spring Data JPA + Flyway migrations.
  * Realtime & Timers: Spring WebSocket (STOMP), without Redis — deadlines are persisted as UTC `timestamptz` directly in PostgreSQL.
  * AI Service: Python 3.12 / FastAPI (called synchronously via HTTP from Core upon score disputes).
  * Authentication: Steam OpenID 2.0 + Email Magic Link, stateless JWT in `HttpOnly` cookies.
* **Input Analysis Artifacts:**
  1. `docs/requirements.md` (36 atomic MVP user stories US-01...US-36, acceptance criteria, and Gherkin scenarios).
  2. `docs/analysis/requirements-digest.md` (13 core entities E1–E13, 60 strict business rules BR-01..BR-60, 25 engineering assumptions ASM-01..ASM-25).
  3. `docs/adr/README.md` and ADR 0001–0009 (architectural decisions established by the team).

## Task
Design an exhaustive, coherent, and strictly typed package of technical contracts for our MVP:

### 1. Data Storage Schema (PostgreSQL DDL)
* Specify the complete PostgreSQL schema covering all 13 entities and 36 MVP user stories.
* For each table define: column names in `snake_case`, precise SQL data types (`UUID`, `VARCHAR`, `TIMESTAMPTZ`, `INTEGER`, `BOOLEAN`, `TEXT`), primary keys (`PRIMARY KEY`), foreign keys (`FOREIGN KEY`) with explicit cascade rules, `NOT NULL` constraints, and default values (`DEFAULT`).
* Enforce all domain invariants and integrity constraints at the database level:
  - `CHECK` constraints for enumerations instead of native PostgreSQL enum types (ADR-0004);
  - `UNIQUE` constraints (e.g. unique team name per discipline `UNIQUE(name, discipline)`, unique active invite link, duplicate entry prevention `UNIQUE(tournament_id, team_id)`);
  - Partial Unique Indexes, specifically ensuring at most one open dispute per match (`CREATE UNIQUE INDEX ... WHERE status = 'OPEN'`);
  - Versioning columns for optimistic locking (`version BIGINT NOT NULL DEFAULT 0`).

### 2. Client ⟷ Core REST API Contracts
* Design a comprehensive catalog of RESTful endpoints covering all 36 MVP User Stories (US-01 ... US-36).
* For each endpoint provide:
  - HTTP method (`GET`, `POST`, `PATCH`, `DELETE`) and canonical RESTful path `/api/v1/...`;
  - Action summary with explicit traceability link to the User Story ID (`US-XX`);
  - Authorization / access level (Public, Authenticated, Captain, Organizer);
  - Request parameters (Path variables, Query parameters, JSON Request Body schema);
  - Successful response format (HTTP status `200 OK`, `201 Created`, `204 No Content` with response JSON schema);
  - Standard error status codes (`400 Bad Request`, `401 Unauthorized`, `403 Forbidden`, `404 Not Found`, `409 Conflict`, `422 Unprocessable Entity`).

### 3. Realtime Messaging Contracts (WebSocket / STOMP)
* In accordance with ADR-0005, specify:
  - WebSocket handshake endpoint: `/ws`;
  - Client subscription topics (Topic Destinations): `/topic/matches/{matchId}/room`, `/topic/tournaments/{tournamentId}/bracket`;
  - Client outbound destinations (Application Destinations): `/app/matches/{matchId}/ready`, `/app/matches/{matchId}/ban`;
  - Structured JSON message payloads for: ready check toggles, map veto outcomes, timer expiration notices, and bracket state updates.

### 4. Internal Core ⟷ AI Service Contract
* In accordance with ADR-0006, formalize the synchronous HTTP contract for the Python FastAPI service:
  - Endpoint `POST /api/v1/ai/analyze-dispute`;
  - Multipart request payload (binary image file + team roster metadata);
  - Structured JSON response schema (extracted score, confidence score, OCR nickname verification report).

### 5. Unified Error Format Specification
* Define a single application-wide error representation adhering to **RFC 7807 (Problem Details for HTTP APIs)** and Spring Problem Details.
* Define all standard fields: `type`, `title`, `status`, `detail`, `instance`, `code` (domain business error code), `timestamp`, and `invalidParams[]` (for form field validation errors).
* Provide an exhaustive catalog of domain error codes (`AUTH_REQUIRED`, `ROSTER_FULL`, `TOURNAMENT_CHECKIN_EXPIRED`, `MAP_ALREADY_BANNED`, `SCORE_MISMATCH`, etc.).

## Output Deliverables Structure
Organize all outputs into the `docs/contracts/` directory:
* `docs/contracts/README.md` — Contracts index, naming conventions, reference enumerations, and User Stories traceability matrix.
* `docs/contracts/data-schema.md` — PostgreSQL relational schema, complete runnable DDL script, and entity relationship specifications.
* `docs/contracts/api-contracts.md` — Exhaustive REST and STOMP API specifications with data models.
* `docs/contracts/error-format.md` — RFC 7807 Problem Details specification and application error codes catalog.
