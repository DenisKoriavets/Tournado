## 1. Issue 1: Database Foreign Key Integrity & Flyway Seeding

### Symptom & Analysis
The database schema (`docs/contracts/data-schema.md` / `V1__initial_schema.sql`) declares:
```sql
created_by_user_id UUID NOT NULL REFERENCES users(id) ON DELETE RESTRICT
```
In early MVP before authentication is fully integrated into the UI flow, attempting to insert a tournament with an arbitrary `created_by_user_id` causes a foreign key constraint violation:
`ERROR: insert or update on table "tournaments" violates foreign key constraint "tournaments_created_by_user_id_fkey"`.

### Refactoring Prompt
```markdown
Create a new Flyway migration `core/src/main/resources/db/migration/V2__seed_system_user.sql`:
Insert an idempotent system organizer record into `users`:
- ID: `00000000-0000-0000-0000-000000000001`
- Email: `system.organizer@tournado.kma.ua`
- Display Name: `Tournado System Organizer`
- Use `ON CONFLICT (id) DO NOTHING;` to guarantee safety across restarts.

In `TournamentService.java`, default the `created_by_user_id` to this system organizer UUID whenever a tournament is created through the public API.
```

## 2. Issue 2: Test Decoupling & Java 26 Byte Buddy Compatibility

### Symptom & Analysis
1. Full `@SpringBootTest` attempts to connect to PostgreSQL on port 5432 during controller unit testing, creating flaky dependencies on external Docker containers.
2. On host machines running JDK 25/26, Mockito/ByteBuddy throws: `Java 26 is not supported by the current version of Byte Buddy - set net.bytebuddy.experimental as a VM property`.

### Refactoring Prompt
```markdown
Refactor `TournamentControllerTest.java` to use Spring Boot slice testing:
1. Annotate with `@WebMvcTest(controllers = TournamentController.class)` and `@MockBean TournamentService tournamentService`.
2. This isolates HTTP serialization, Jackson JSON binding, and RFC 7807 `GlobalExceptionHandler` without requiring a live PostgreSQL instance.
3. In Maven Surefire plugin or test command, pass `-Dnet.bytebuddy.experimental=true` to enable dynamic agent loading on modern JDKs.
```

## 3. Issue 3: Local Timezone Parsing in Frontend Date Utilities

### Symptom & Analysis
In `frontend/src/utils/date.test.ts`, constructing input strings via `new Date(now + 100000).toISOString().slice(0, 16)` produced UTC strings (e.g. `07:31`). When `<input type="datetime-local">` parses this value without a timezone suffix, it interprets it as local time (Europe/Kyiv, UTC+2). In the morning, `07:31 local` was 2 hours in the past compared to `09:31 Kyiv time`, triggering false-positive `deadlineInPast` validation failures.

### Refactoring Prompt
```markdown
In `frontend/src/utils/date.ts` and `date.test.ts`:
1. Export `toLocalDatetimeInputString(date: Date): string` which formats hours and minutes using `date.getHours()` and `date.getMinutes()`.
2. Refactor tests to construct future datetime inputs using `toLocalDatetimeInputString(new Date(now + 2 * 3600 * 1000))` instead of naive ISO string slicing.
```

## 4. Issue 4: React Testing Library DOM Query Ambiguity

### Symptom & Analysis
In `TournamentForm.test.tsx`, calling `screen.getByText('Brawl Stars')` failed because both the card title (`<div class="font-bold">Brawl Stars</div>`) and the subtitle description matched.

### Refactoring Prompt
```markdown
In `frontend/src/components/TournamentForm.test.tsx`:
```

## 5. Issue 5: Eliminating AI Slop, Academic Clutter, and Refactoring to Broadcast Studio UI

1. Academic tags such as `Vertical Slice 1 • US-07..US-11`, `Production Ready`, and inline `(US-07)` markers were rendered in buttons and headers.

3. A raw diagnostic box (`Backend: UP | DB: UP | timestamp`) was pinned in the header next to primary actions.
4. Hardcoded client mock tournaments (`DEMO_TOURNAMENTS`) masked whether true PostgreSQL persistence was operating.
5. Inconsistent system emoji soup was used instead of clean vector icons.

### Refactoring Prompt
```markdown
Refactor the entire frontend UI into a professional "Broadcast Studio" (Tier-1 Esports Arena) design:
1. Create `frontend/src/components/icons/Icons.tsx`: purely vector SVG icons with zero system emojis.
2. Replace legacy centered dialog with `TournamentDrawer.tsx`: a responsive, accessible right slide-over drawer with tabs (Огляд, Розклад та слоти, Сервер та карти).
3. Replace 541-line form with `TournamentFormModal.tsx`: an ergonomic 2-step wizard (Step 1: Discipline & Name -> Step 2: Slots, Schedule & Server) with quick presets and RFC 7807 error translation.
4. Clean up `App.tsx`: sleek dark navigation bar, honest PostgreSQL persistence with an attractive empty state when the DB is clean, removing all rubric tags and debug cards.
5. Ensure 100% test pass rate across all Vitest suites and 0 TypeScript build errors.
```
