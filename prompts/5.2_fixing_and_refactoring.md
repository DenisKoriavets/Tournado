## 1. Issue 1: Database Foreign Key Integrity & Flyway Seeding

### Symptom & Analysis
The database schema (`docs/contracts/data-schema.md` / `V1__initial_schema.sql`) declares:
```sql
created_by_user_id UUID NOT NULL REFERENCES users(id) ON DELETE RESTRICT
```
In early MVP before authentication is fully integrated into the UI flow, attempting to insert a tournament with an arbitrary `created_by_user_id` causes a foreign key constraint violation:
`ERROR: insert or update on table "tournaments" violates foreign key constraint "tournaments_created_by_user_id_fkey"`.

### Refactoring Prompt
```markdown
Create a new Flyway migration `core/src/main/resources/db/migration/V2__seed_system_user.sql`:
Insert an idempotent system organizer record into `users`:
- ID: `00000000-0000-0000-0000-000000000001`
- Email: `system.organizer@tournado.kma.ua`
- Display Name: `Tournado System Organizer`
- Use `ON CONFLICT (id) DO NOTHING;` to guarantee safety across restarts.

In `TournamentService.java`, default the `created_by_user_id` to this system organizer UUID whenever a tournament is created through the public API.
```

## 3. Issue 3: Local Timezone Parsing in Frontend Date Utilities

### Symptom & Analysis
In `frontend/src/utils/date.test.ts`, constructing input strings via `new Date(now + 100000).toISOString().slice(0, 16)` produced UTC strings (e.g. `07:31`). When `<input type="datetime-local">` parses this value without a timezone suffix, it interprets it as local time (Europe/Kyiv, UTC+2). In the morning, `07:31 local` was 2 hours in the past compared to `09:31 Kyiv time`, triggering false-positive `deadlineInPast` validation failures.

### Refactoring Prompt
```markdown
In `frontend/src/utils/date.ts` and `date.test.ts`:
1. Export `toLocalDatetimeInputString(date: Date): string` which formats hours and minutes using `date.getHours()` and `date.getMinutes()`.
2. Refactor tests to construct future datetime inputs using `toLocalDatetimeInputString(new Date(now + 2 * 3600 * 1000))` instead of naive ISO string slicing.
```
